# Scientific Software Project Instructions

This repository contains an active technical research project.

## Core rules

1. Scientific correctness precedes optimisation.
2. Functional correctness precedes performance claims.
3. Never silently change physical, mathematical or architectural assumptions.
4. New complexity must answer an explicit research question.
5. Establish trusted baselines before acceleration, optimisation or AI.
6. Separate algorithm execution from transport, dispatch, queueing and orchestration overhead.
7. Important interfaces require explicit contracts.
8. Important results require provenance.
9. Negative results are valid research outcomes.
10. Stretch work must not redefine the core project completion criterion.
11. Consequential technical decisions must be recorded.
12. Principal results must reproduce from a clean checkout.
13. Simulation results must never be represented as physical measurements.
14. Modelled performance must be distinguished from measured hardware performance.
15. All scientific claims require corresponding evidence.
